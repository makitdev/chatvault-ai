# Export

ChatVault AI exports one stored conversation at a time as:

- **PDF** using ReportLab.
- **DOCX** using python-docx.

Both formats are generated from the SQLite message text. The exports do not call
Ollama, ChromaDB, or the network.

## From the app

1. Open a conversation from the Library or Dashboard.
2. Select **Export PDF** or **Export DOCX**.
3. The browser downloads the generated file.

Generated files are also written to `storage/generated/` with the conversation ID
as the filename:

```text
storage/generated/<conversation-id>.pdf
storage/generated/<conversation-id>.docx
```

Existing files with the same name are overwritten on the next export.

## From the API

```bash
curl -OJ http://127.0.0.1:8000/api/v1/conversations/<conversation-id>/export/pdf
curl -OJ http://127.0.0.1:8000/api/v1/conversations/<conversation-id>/export/docx
```

The response is a file download:

| Format | Media type |
| --- | --- |
| PDF | `application/pdf` |
| DOCX | `application/vnd.openxmlformats-officedocument.wordprocessingml.document` |

If the conversation does not exist, both endpoints return HTTP `404` with
`Conversation not found.` If generation fails, they return HTTP `500` with
`Unable to generate PDF.` or `Unable to generate DOCX.`

## Supported formatting

The shared Markdown block parser supports a practical subset of Markdown:

| Construct | PDF | DOCX |
| --- | --- | --- |
| Headings (`#` to `######`) | Yes, levels capped at 3 for styling | Yes, levels capped at 4 |
| Paragraphs | Yes | Yes |
| Bullet lists | Yes | Yes |
| Numbered lists | Yes | Yes |
| Task lists (`- [ ]`, `- [x]`) | Yes, checkbox glyphs | Yes, checkbox glyphs |
| Block quotes (`>`) | Yes, styled callout | Yes, Quote style |
| Fenced code blocks | Yes, monospaced, shaded | Yes, monospaced, shaded |
| Pipe tables | Yes, real tables | Yes, real Word tables |
| Horizontal rules | Yes | Yes |
| Inline code, bold, italic | Basic inline formatting | Basic inline formatting |

The parser is not a full CommonMark renderer. Complex nested Markdown, raw HTML,
images, footnotes, and arbitrary extensions are not rendered as rich content.
Inline HTML tags are stripped where the parser handles text.

## PDF details

The PDF export uses an A4 layout with:

- A navy title panel containing the brand, title, and conversation ID.
- A running header on later pages.
- Role labels: `YOU` for user messages and `CHATGPT` for assistant messages.
- A footer with the generating application and page number.
- DejaVu Sans for text and DejaVu Sans Mono for code.

!!! warning "Linux font path dependency"
    The PDF generator loads fonts from
    `/usr/share/fonts/truetype/dejavu`. On Debian/Ubuntu install
    `fonts-dejavu-core`. If the files are missing, PDF export returns HTTP 500.
    This path is not configurable in `v1.0.0`.

Emoji and terminal symbols are normalized or removed because the bundled fonts
do not contain the full emoji set. Examples: box-drawing characters become ASCII
equivalents, check marks become `✓`, and remaining pictographs are dropped.

Code block indentation is preserved using non-breaking spaces. Very long
conversations can produce large PDFs; generation is synchronous and may take
time.

## DOCX details

The DOCX is editable in word processors. It includes:

- The conversation title and conversation ID.
- A rule below the metadata.
- A heading per message using the role name.
- Real Word tables for pipe tables.
- Shaded code paragraphs with a monospaced font.
- List, quote, and task-list styling.
- A centered footer: `Generated by ChatVault AI`.

The document uses the font names DejaVu Sans and DejaVu Sans Mono. The file does
not embed fonts; the viewer may substitute available fonts.

## Filename and path safety

The output path is built from the conversation ID, which must match:

```text
[A-Za-z0-9_-]{1,100}
```

Only `.pdf` and `.docx` extensions are accepted by the path builder. This
prevents path traversal through the conversation ID. Share IDs are restricted to
the same character class at import time.

## Current limitations

- One conversation per request; no batch export.
- No combined library export.
- No HTML, Markdown, JSON, or plain-text export endpoint.
- No background job or progress stream.
- No automatic cleanup of `storage/generated/`.
- PDF export depends on Linux DejaVu font paths.
- Very large conversations are generated in the request and may be slow.
